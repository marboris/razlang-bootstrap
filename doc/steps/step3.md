جدید:
خب هدف ما این هست که این زبان بیشتر مانند یک زبان اسکریپت نویسی باشد و خب چند تا ایده اراعه میدم.
کامپایلر ما نمیخواد همه چیز را به C++ بسپارد. مثل متد های include در C++. در هرجایی که فقط نیاز شد.
پس هدف ما از متد include ای که خودمان قرار هست طراحی کنیم مطابق با چیزی که ما میخواهیم قابل انجام هست. در نهایت کامپایلر نهایی ما باید فایل Raz ای که برای کامپایل دریافت میکند.. هرچند که include ها یا import هایی در زبان انجام شده باشد.. کامپایلر باید تمام ان کد ها را واقعا هنگام کامپایل include کند و در فایل اصلی قرار دهد. پس شدنی هست. یعنی برای هر فایل ای که قرار است در اینده include شود و یک فایل Raz جدا هست مثل کتابخانه.. در نهایت با include هنگام کامپایل include میشود در همان فایلی که include انجام شده و در همان لاین. این یک import خاص برای یک متد یا متغیر خاص نیست. واقعا کل فایل را شامل میشود با همه چی. ایده جدیدی هست اما شاید استاندارد نباشد و خطرناک باشد. پس اینجا واقعا همه چیز public میشود و نیازی نیست مشخص شود.

include هم پس برای مثال میتواند در یک شرط استفاده شود یا حتی اخر فایل. مهم نیست.
فقط باید یک استثنا برای include خودمان و include فایل هدر های واقعی C++ قاعل شویم.
import یا include هایی که قرار هست مستقیم یک فایل هدر C,C++ را قرار دهد از متد use استفاده کنیم. مثلا:
use linux;
برای مثال در اینجا linux یک هدر استاندارد خود زبان و کامپایلر ما هست که در اینده این را مشخص میکنیم. یا
use "some_header.hpp";
این هم میشود برای هدر های واقعی. که میتوانیم حتی خودمان هم ازش استفاده کنیم.
و هم کاربر هم استفاده کند. در نهایت ما هر متدی که قرار هست بسازیم هم طبق شرط public هست. یعنی هم خودمان و هم کاربر میتواند ازش استفاده کند.
در raz هم چیزی مثل new یا OOP به صورت کلی نداریم. اگر هم در فایل های هدر داشتیم خیلی راحت میتوانیم فقط از انها استفاده کنیم مستقیم. ولی باید در ان فایل های class خودش باز شده باشد. پس متد های داخل use مستقیم استفاده میشوند و در فایل به صورت هدر.. و به ان هم دست نمیزنیم.. متد های use هم باید حتمی در top file باشند. و واقعا تبدیل میشوند به #include در نهایت (C++)
nullptr رو داریم. struct هم داریم و مشابه C,C++ باید باشد.
تایپ های این شکلی هم جالب نیستن در نسل های بعدی: -> void
مثل خود C,C++ تایپ گذاری شود تا مشکلی در تبدیل انها وجود نداشته باشد. و کل تایپ های C هم باید داشته باشیم و ساده هستن. میتوانیم حتی تایپ هایی در یک فایل هدر رو در raz استفاده کنیم.
چیزی مثل extern, export و .. هم نداریم همونطور که توضیح دادم.
Ref<T> نمیدونم چیه و جالب نیست. تایپ ها میتوانند مثل C باشند. ساده ترین حالت و نزدیک به hardware.
همه چیز منطقی و نزدیک به hardware ساخته میشوند و این عملا یک زبان low-level و نزدیک به hardware هست و با GNU بیلد گرفته میشود و از مزایای بهینه سازی های سخت افزاری و کامپایلر هم بهره میبرد. در نهایت برنامه ای که با raz ساخته میشود از RIR یک برنامه پرسرعت هست و بدون overhead و چیز های اضافه.
پس عملا چیزی مثل let, var هم نداریم.
const, static, void, other types...
