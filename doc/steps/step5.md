خب من میگم به طور کلی var رو نداشته باشیم و let کافی هست.
یک هدفی که فراموش کردم!
Raz قرار هست یک زبان memory safe باشد و هدف ما در خود زبان و کامپایلر هم همین هست. که تا جای ممکن هرچیزی را خودمان خودکار سازی کنیم.
عملا باید بگم پوینتر ها رو در Raz نداریم! البته بجز هدر های native که خودشان استفاده میکنند. این خودکار سازی باید توی زبان خودمان باشد. نمیخوام بگم چون هدر های نیتیو هم قابلیت استفادشون رو داریم کلا پوینتر ها هم نداشته باشیم. این نمیشود. پوینتر قابلیت استفادش باشه اما توی خود زبان میخوام اصلا نیازی به استفاده از پوینتر نباشه. توی کامپایلر های نسل بعد برای تبدیل سورس شاید بخوایم بیشتر از نوع های auto, nullptr​, make_unique بیشتر استفاده کنیم. البته بگم چون سورس نزدیک به hardware هست شاید دلمان نخواهد ولی جزو پلن هست که raz یک زبان memory safe هست. در نهایت استفاده از try catch هم پیشنهاد میکنم و توی raz داشته باشیمش. و throw. ولی شاید توی سرعت تاثیر بگذارد که پیشنهاد نمیشود.
عملا پس استفاده از char* در raz پیشنهاد نمیشود. در اینده شاید بخوایم ان را منسوخ کنیم. ولی توی نسل های اولیه استفاده و داشتن ان برای توسعه خود کامپایلر هسته نیاز هست که همه چیز رو داشته باشیم.
ما فعلا داریم خود کامپایلر رو برای کامپایلر بهینه و توسعه میدیم و لایه های اخر کامپایلر اماده میشود برای خروجی کاربر.
این نسل بندی جالب هست و توی توضیحات قبلی هم ان را برای توسعه کامپایلر استفاده کن. از فرمولش استفاده کن و مثال بزن برای بقیه توسعه دهنده ها.

چیز هایی که در C++ داشتیم مثل تابع main اجباری و توی raz نداریم.. برای استفاده از argv ها در کامپایلر میتوانیم argv ها و .. که C++ به ما میدهد رو ما در کامپایلر در یک متغیر global تعریف کنیم.

این اصلاحیات رو با جزییات توی داکیومنت بزار.
