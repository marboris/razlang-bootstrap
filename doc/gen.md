# شماره‌گذاری و چرخه‌ی عمر نسل‌ها

این سند قرارداد رسمی نسل‌هاست. هر نسل دو نقش دارد: **artifact ساخته‌شده از نسل قبل** و **compiler عملیاتی نسل خودش**.

## مدل ساخت

برای `n >= 1`:

```text
gen_n = B(C_(n-1)(S_n))
```

یعنی compiler نسل `n-1` سورس نسل `n` را به C++/artifact قابل اجرا تبدیل می‌کند. شرط لازم برای ساخت فقط این است:

```text
S_n ∈ L_(n-1)
```

یا در سطح capabilityها:

```text
uses(S_n) ⊆ F_(n-1)
```

## بعد از freeze

بعد از freeze، `gen_n` دیگر برای کامپایل `S_n` لازم نیست. نقش آن این است:

```text
gen_n → S_(n+1) → gen_(n+1)
```

و همچنین:

```text
gen_n → برنامه‌های عادی نوشته‌شده در L_n
```

پس `gen0` سازنده‌ی Gen1 است، `gen1` سازنده‌ی Gen2 است، و همین الگو ادامه دارد.

## self-compile

کامپایل دوباره‌ی `S_n` با `gen_n` **الزام نیست**. هر نسل مجاز است internal API، syntax یا قابلیت‌هایی را تغییر دهد که باعث شوند `S_n` دیگر با `gen_n` سازگار نباشد. این موضوع عمداً اجازه‌ی breaking redesign بین نسل‌ها را می‌دهد.

اگر reproducibility لازم باشد، می‌توان یک `rebuild-check` اختیاری اجرا کرد.

## نگهداری فایل‌ها

```text
generations/genN/
├── src/        سورس compiler همان نسل
├── final/      bundle قابل ساخت همان نسل
├── examples/   برنامه‌های نوشته‌شده با L_N
├── bin/        compiler منجمد همان نسل
├── build/      خروجی موقت ساخت
└── gen.json    متادیتای نسل
```

قانون مهم: هر چیزی زیر `examples/` پس از freeze باید با **همان `genN`** کامپایل شود، نه compiler نسل قبل.
